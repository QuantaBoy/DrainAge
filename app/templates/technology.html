Forecast engine

Reading this device…

The speed comes from never running the same storm twice, and from computing the likely storms before anyone asks.

Techniques

  • Computed ahead

    The live forecast and the 15, 30, 60 and 100 mm/h storms are ready before anyone asks, and the live one refreshes as the rain feed updates.

  • Compressed answers

    A finished forecast is kept gzip-compressed and sent as it is: about 3.4 MB instead of 27 MB, with no work on a repeat request.

  • Shared requests

    Requests for a storm already being computed wait for that run instead of starting another.

  • Model on disk

    The built city model is saved, keyed on every input file, so a restart loads it in seconds instead of rebuilding it for minutes.

  • A* routing

    The safe route is found with A*, which settles about a fifth of the junctions Dijkstra does for the same answer.
