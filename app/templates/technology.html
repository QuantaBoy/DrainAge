Technology

What is new in this system, how it runs, and every resource it is built from. The numbers in the lower sections are read live from the server, not written in.

Innovation

Flood warning in Indian cities today stops at the ward, or looks up pre-computed scenarios. This system simulates every street, live, from the rain forecast to the drain it fills.

  1. Street by street, not ward by ward

    Depth in centimetres on each street stretch, every 5 minutes for the next 3 hours.

    Today: ward-level warnings (I-FLOWS Mumbai) or scenario lookup (C-FLOWS Chennai).

  2. Rain, ground and drains in one live model

    Rain soaks in or runs off by SCS curve number, flows over a 30 m terrain model, enters the drains up to their Manning capacity, and comes back up at the manholes when they are full.

    Today: rainfall forecasts with no link to the drains that carry it.

  3. Paper maps turned into a working drain network

    92 scanned GCC ward sheets read by OCR into 7,951 manholes and 12,566 drains, joined with the city's 10,257-drain survey into one directed graph.

    Any city with drain maps, even on paper, can be onboarded the same way.

  4. Terrain corrected to the street

    The satellite terrain is corrected to surveyed manhole levels, building clutter is taken out, and rivers and canals are cut in so they carry water instead of damming it.

    Its height datum is checked point by point: see Resources.

  5. Drain condition as a control

    Run any storm with the drains at full, half, a quarter or no capacity, and see which streets flood and which manholes overflow.

    Desilting can target the drains that matter, not a fixed schedule.

  6. Flood-safe routes for any trip

    A* and Dijkstra over 134,000 road junctions, using the water expected at the time of travel, through an open API that navigation apps and emergency services can call.

    Tested against the real 2015 flood record on zones not used for tuning.

Forecast engine

Reading this device…

The speed comes from never running the same storm twice, and from computing the likely storms before anyone asks.

Techniques

  • Computed ahead

    The live forecast and the 15, 30, 60 and 100 mm/h storms are ready before anyone asks, and the live one refreshes as the rain feed updates.

  • Compressed answers

    A finished forecast is kept gzip-compressed and sent as it is: about 3.4 MB instead of 27 MB, with no work on a repeat request.

  • Shared requests

    Requests for a storm already being computed wait for that run instead of starting another.

  • Model on disk

    The built city model is saved, keyed on every input file, so a restart loads it in seconds instead of rebuilding it for minutes.

  • A* routing

    The safe route is found with A*, which settles about a fifth of the junctions Dijkstra does for the same answer.
